# D-095 · The public-website page stores the organisation's main website AND, optionally, a public address for the portal's public pages

**Date:** 2026-11-09  
**Status:** in force

**Question:** D-085 names "the organisation's public address" as one thing the new Admin →
Public website page sets. It could mean (1) the organisation's main website, for example
www.ourchurch.org, which the portal does not run and inside which the portal's content
appears through the pasted script, frame or feed (D-056); or (2) a separate address for the
portal's own public pages, for example events.ourchurch.org, which the organisation points at
the portal so public visitors never touch the address members sign in at. Which?

**Answer:** **both.** The main website is recorded (the set-up check confirms it answers, and
it is suggested for the list of websites allowed to frame, D-082). A public address for the
portal's public pages may also be given; it is **optional**, and without it the public pages
use the portal's own address plus a per-organisation path. The owner, 9 November 2026,
choosing the recommended option after asking for the two meanings to be explained.

**Rules out:** recording only one of the two.

**Where:** #493 package P3 stores and checks both; package P4 makes the public door answer on
the public address. Each public address belongs to exactly one organisation, enforced by the
database, because two organisations sharing one would show one's content to the other's
visitors. Related: D-056, D-082, D-085.

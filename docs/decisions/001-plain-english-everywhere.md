# D-001 · Plain English everywhere

**Date:** 2026-09-07  
**Status:** in force

**Question:** how should everything be written?
**Answer:** plain everyday English — replies, code comments, commit messages,
issues, every `.md`, the in-app help, and everything an end user sees. The owner's
reason: jargon "can sometimes be confusing even for some technically proficient
users/developers".
**Rules out:** unexplained abbreviations; impressive-sounding filler; lowering the
standard of the work to simplify the words.
**Where:** `~/.claude/CLAUDE.md`, `.claude/CLAUDE.md` → "Plain English".

**Issue:** [#752](https://github.com/MWBMPartners/WebMS-Intra/issues/752) —
the standing issue for decisions that are not about a feature.

---

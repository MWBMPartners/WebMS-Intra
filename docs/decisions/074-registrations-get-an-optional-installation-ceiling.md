# D-074 · Registrations get an optional installation ceiling, off by default

**Date:** 2026-11-07  
**Status:** in force

**Question:** a registration's name and contact details are kept for a number of
days after the event — set by each organisation (`events.registrationRetentionDays`)
and optionally by each event. Nothing caps either by the installation's figure, unlike
attendance (#668) and anonymous check-ins (#685). Should the installation's figure be a
ceiling here too (#816)?

**Answer:** **an OPTIONAL ceiling, off by default.** The installation's administrator can
set a maximum; until they do, nothing changes. The giving-records approach (D-032),
because a retention period may be a legal requirement and a forced ceiling could make an
organisation delete details it must keep. The owner, 7 November 2026.

**Rules out:** a ceiling always in force from the start; leaving it uncapped as a
permanent choice.

**What it does NOT settle:** whether a ceiling set below an organisation's existing figure
is refused (as D-032's giving ceiling is) or applied — follow D-032 unless a measured fact
makes that unworkable.

**Where:** #816. Related: D-013, D-032, #668, #685, #810.

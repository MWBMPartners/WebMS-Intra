# D-052 · Portal content on the public website is in the first release

**Date:** 2026-11-05  
**Status:** in force

**Question:** #493 asks for content written in the portal — notices, events,
projects — to be readable on the organisation's ordinary public website, not
only on the portal's own address. D-041 listed what goes into the first usable
release and did not mention #493 either way. Is it in, deferred, or in as a
cut-down read-only feed?

**Answer:** **in the first release, in full** — not the cut-down feed. The
owner, 5 November 2026, asked alongside two other release-scope questions.

**Rules out:** deferring it with an issue, which was the recommendation on the
grounds that it is the largest remaining item and the only one that opens a new
way in from outside. It also rules out the smaller "read-only feed of things
already public" version, which would have published a simple list a website
could pull in with no new pages and no new settings. That option is NOT what
#493 asks for, and choosing the full answer means the work includes deciding
what may be shown publicly and who decides it.

**What this costs, said plainly:** it is the longest item left in the queue and
it pushes the release out. It also adds a surface reachable without signing in,
which has to be designed as carefully as the sign-in gates were — a new public
way in is where #478's unreachable-but-ungated widget would have become live.

**Where:** #493; the release queue; `.claude/HANDOFF.md`.

**Supersedes in part:** D-041, which fixed the first release's scope for the
partly-built features and was silent on this one. D-041 otherwise stands.

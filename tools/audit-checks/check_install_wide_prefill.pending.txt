# Forms that prefill a merged setting their own Save writes installation-wide (#674).
#
# Each line is a page that already had this shape when the check was written on
# 30 October 2026. The check gates from the start so that NO NEW page can join
# them; `--strict` fails while any line remains, which is what stops this list
# becoming permanent.
#
# WHY THEY ARE NOT ALL FIXED AT ONCE. The fault is one line of reasoning repeated
# fifteen times, but the fix is not mechanical: each page has to be read field by
# field to see which boxes its own Save really writes installation-wide, and a
# page may legitimately show a merged value BESIDE an installation one ("your
# organisation currently uses..."). Changing fifteen pages on a guess is how a
# sweep introduces more faults than it removes.
#
# THE SHAPE OF THE FAULT, so each line can be judged without re-deriving it:
# `$SETTINGS` is already merged by the time a page runs, so a box filled from
# `App::settings()` shows the OPEN ORGANISATION's value while Save writes the row
# with `siteID IS NULL` -- the INSTALLATION's. A global administrator opens the
# page while in an organisation that has its own override, sees that override,
# and presses Save without touching anything. It is now everyone's.
#
# THE FIX, which one field already demonstrates: read from
# `Portal\Core\InstallationSettings::layer()`, which holds the installation-wide
# rows alone. `admin/settings/repeats` and `transcription.monthCapPence` do this.
#
# Delete a line when that page reads every installation-wide field from the
# layer. The check FAILS on a line that no longer has the fault, so this list
# cannot quietly go stale.

# ── EMPTIED 11 NOVEMBER 2026 (#943) ───────────────────────────────────────────
#
# All thirteen pages that were listed here now fill every installation-wide box
# from the installation's own rows, through `InstallationSettings::value()` (or
# `::layer()`), and say so on the page when the open organisation holds a value
# of its own (`InstallationSettings::differsHere()`, the one notice
# `_core/templates/install-wide-notice.php`). The behaviour is driven over HTTP,
# page by page, by `tools/install-wide-prefill-selftest.php`: an organisation is
# given its own value, a global administrator opens the page inside it, presses
# Save untouched, and the installation's row and the organisation's row must both
# be unchanged. Nothing may be added to this list: `--strict` now passes, and a
# NEW page with the fault fails the check outright.
#
# The header's warning stands for whoever reads a future finding: a page that
# reads the layer for ONE field and the merged array for another is still not
# reported by the check. The self-test above is what covers the thirteen.

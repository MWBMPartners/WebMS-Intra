# Path: tools/audit-checks/check_inline_scripts_have_nonce.exempt.txt
#
# Files that are NOT held to the rule "a script written into a page carries the
# nonce; no handler on an element". Read by
# tools/audit-checks/check_inline_scripts_have_nonce.py, which explains the rule
# and why it exists (#625).
#
# One entry per line:   <file>  <reason>  <the words that explain it>
#
# The reason is one of four:
#   no-rule     The page draws its own <!doctype> and never includes the
#               standard header (web/_core/templates/header.php), so no script
#               rule is sent with it and its scripts and handlers run.
#   own-rule    The page sends a script rule of its own.
#   not-a-page  Not a portal page: a bundle made by others, or a static file a
#               browser opens by itself.
#   waiting     Held by other work today. The exact change is written here and
#               the line goes when that work has landed. (None at the moment.)
#
# THE CHECK TESTS THIS LIST ITSELF. A file marked no-rule or own-rule that
# includes the standard header is refused, whatever this list says. A line whose
# file has nothing left to exempt is refused as stale. A line for a file that is
# not there is refused. And the list may not grow: the check holds today's count
# (MOST_EXEMPTIONS) and fails on a longer list.
#
# NEVER ADD A LINE TO MAKE A FAILURE GO AWAY. If the check fails on a page that
# uses the standard header, the page is broken in a browser: give the script the
# nonce, or turn the handler into a listener. A new stand-alone page should be
# written clean from the start, so that it needs no line here.
#
# BEFORE WRAPPING ONE OF THE no-rule PAGES IN THE STANDARD HEADER: every script
# and handler in it stops working the moment the header's rule is sent. Fix them
# first, then remove the page's line (the check will insist).
#
# Package:   Portal\Tools
# Author:    MWBM Partners Ltd (t/a MWservices)
